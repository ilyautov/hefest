# Как участвовать

Спасибо за интерес. Проект простой в устройстве и строгий в одном месте — в отношении к
данным. Ниже то, что нужно знать до первого PR.

## Правило номер один

**Нормативка не выдумывается. Никогда.**

ПДК, ОБУВ, IDLH, коды ФККО, номера ООН, классы опасности, номера и названия ГОСТ, порядок
первой помощи, GHS-классификация — каждое такое значение приходит из авторитетного источника
и несёт провенанс (`source_tier`, `confidence`, цитата). Где источника нет — пишем «нет
данных» и оставляем пропуск видимым.

Три следствия, которые чаще всего нарушают по невнимательности:

1. **Единицы не пересчитываются.** ppm не превращается в мг/м³, °F не превращается в °C.
   Если единицы расходятся — сравнение не выполняется, выводится честное «сверьте вручную».
2. **Типовое не выдаётся за паспортное.** Значение по химической группе помечается
   `baseline` и несёт дисклеймер. Смешивать градации нельзя.
3. **Правдоподобное — не то же самое, что верное.** Заполнить пробел «разумным» значением
   хуже, чем оставить пустым: пустое поле видно, выдуманное — нет.

PR, нарушающий это правило, не мержится, каким бы удобным ни было поведение.

## Что особенно нужно проекту

- **Сверка нормативных значений с бумажным первоисточником** — самый ценный вклад. Нашли
  расхождение? Откройте issue по шаблону «Спор о нормативном значении»: он требует источник
  и воспроизводимую команду.
- **Ингест реальных паспортов** (грязные сканы, OCR, таблицы) — главный неразобранный
  участок, см. `LIMITATIONS.md`.
- **Тесты на контур честности.** Любой новый способ доказать, что система не врёт.
- **Обходы контура честности** — см. `SECURITY.md`, они принимаются как вклад.

## Порядок работы

```bash
git clone git@github.com:ilyautov/hefest.git && cd hefest
python3 -m pip install -r requirements/dev.txt
make test          # офлайн-сьют: без Ollama, без сети, без индекса
make run           # сервис на :8012 в лексическом режиме
```

Ветку заводите от `main`, называйте по смыслу (`feat/`, `fix/`, `docs/`, `chore/`).
Коммиты — по-русски, в повелительном наклонении, с указанием области.

## Требования к PR

- **Тест написан до реализации** (TDD) и падает без неё.
- **`make test` зелёный офлайн.** Сьют обязан проходить у человека, который просто склонировал
  репозиторий: без Ollama, без сети, без собранных эмбеддингов.
- **Если тронут контур честности** (отказ, провенанс, градация источника, запрет пересчёта) —
  в PR есть тест, доказывающий, что честность не ослабла. Это отдельный пункт чек-листа, и он
  проверяется вручную.
- **Числа в документации сверены с кодом и данными**, а не взяты по памяти. Счётчики отдаёт
  `GET /health` и `GET /quality`.
- **Никаких секретов и данных предприятия в diff.** Перед push прогоните `make guard`.
- Хронику заметных изменений ведём в `WORKLOG.md`, пользовательские — в `CHANGELOG.md`.

## Стиль кода

Проект намеренно скромен в зависимостях: ядро — стандартная библиотека плюс FastAPI и
лексический стек. Тяжёлое (torch, transformers, easyocr) грузится лениво и только для
опциональных путей. Не добавляйте зависимость, без которой можно обойтись.

Модули в `engine/` изолированы и имеют самотест в `__main__` — запуск `python3 engine/<модуль>.py`
должен работать без сервиса. Сохраняйте это свойство: оно позволяет проверять логику отдельно
от HTTP.

Комментарии объясняют **почему**, а не **что**. Особенно там, где код намеренно отказывается
что-то делать: без пояснения следующий человек «починит» этот отказ.

## Проверка UI

Экраны — статический HTML со своим `<style>`, без сборки. Мобильную вёрстку меряйте через
Playwright `getBoundingClientRect` на ширине 390px: пиксельный скрин узкого окна headless Chrome
на macOS врёт (окно не сужается ниже ~450px и режет правый край).

## Поведение

Технические разногласия решаются доказательством: источник, команда, наблюдаемый результат.
Ожидания к участникам — в `CODE_OF_CONDUCT.md`, порядок принятия решений — в `GOVERNANCE.md`.
