# Ollama-MCP: сознательный доступ Cowork-агента к твоей Ollama

Мост между изолированным агентом (Claude в Cowork) и локальной Ollama на твоей машине. Тот же паттерн, что Anthropic MCP Tunnels: сервер живёт у тебя, видит `localhost:11434`, отдаёт агенту узкий набор инструментов. Данные не уходят с машины.

## Зачем

Песочница агента изолирована и до твоей Ollama не дотягивается напрямую. MCP-сервер на твоей стороне это чинит и одновременно служит границей доверия: агент получает ровно `embed`, `generate`, `list`, и ничего больше.

## Установка (macOS, проверено)

```bash
# зависимости тем же python, что увидит Cowork:
<путь-к-python3.11> -m pip install mcp httpx

# модели Ollama (один раз):
ollama pull bge-m3        # эмбеддинги, сильный русский
ollama pull qwen2.5:7b    # генерация, хороший русский

# проверка, что сервер стартует:
<путь-к-python3.11> <путь-к-репозиторию>/ollama-mcp/server.py
# (должен запуститься без ошибок; Ctrl+C чтобы остановить)
```

## Подключение в Cowork

Открыть конфиг MCP (файл `~/Library/Application Support/Claude/claude_desktop_config.json`,
либо Settings → Connectors → добавить MCP) и добавить запись:

```json
{
  "mcpServers": {
    "ollama-bridge": {
      "command": "<путь-к-python3.11>",
      "args": ["<путь-к-репозиторию>/ollama-mcp/server.py"],
      "env": { "OLLAMA_HOST": "http://127.0.0.1:11434" }
    }
  }
}
```

Сохранить, **перезапустить Cowork**. После рестарта у агента появятся инструменты
`ollama_health`, `ollama_embed`, `ollama_generate`, `ollama_list_models`.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `ollama_health` | жива ли Ollama, какие модели локально |
| `ollama_list_models` | список разрешённых локальных моделей |
| `ollama_embed(text, model)` | эмбеддинг текста (дефолт bge-m3) |
| `ollama_generate(prompt, model, system)` | генерация (дефолт qwen2.5:7b) |

## Чек-лист безопасности (граница доверия)

- **Белый список моделей.** `ALLOWED_MODELS` ограничивает, что агент может дёрнуть. Произвольную модель не запустит.
- **Только инференс.** Сервер умеет embed/generate/list. Никаких `pull`, `rm`, shell, файловых операций.
- **Локальный bind.** Ходит только на `127.0.0.1:11434`. Наружу ничего не открывает (исходящих туннелей нет, в отличие от облачного варианта).
- **Аудит.** Каждый вызов пишется в лог (модель, длины вход/выход). Видно, что агент делал.
- **Что отдаём / что нет.** Отдаём: инференс на публичных/рабочих текстах. НЕ отдаём: сырые приватные документы без твоего ведома, любые записи/изменения.

## Как это обобщается

Этот сервер это первый инстанс паттерна из задачи «MCP-мост» (`personal/TASKS.md`). По той же схеме потом подключаются БД, файлошары, внутренние API: сервер на твоей стороне + узкие инструменты + аудит + белый список. Для химзавода с КИИ это и есть архитектура «AI через контролируемую границу, а не внутрь контура».
