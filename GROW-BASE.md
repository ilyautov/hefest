# Как вырастить базу с 48 до полного перечня ГН 2.2.5.3532-18 (2495 веществ)

## ВАЖНО: PDF Роспотребнадзора это СКАН (не подходит)

Проверено: `GN_sreda_obitaniya_compressed.pdf` это скан, 469 страниц-картинок, текстового слоя ноль. Парсить его нельзя, а OCR'ить ПДК опасно (распознавание путает цифры/точки, а это здоровье людей). **Используем HTML-источник с текстовым слоем.**

## Рекомендуемый путь: HTML (meganorm)

```bash
cd ~/personal/pilots/rag-sds/engine
pip install beautifulsoup4 lxml

# 1. Открой в браузере страницу ГН 2.2.5.3532-18:
#    https://meganorm.ru/Data2/1/4293737/4293737770.htm
#    Сохрани её: Cmd+S -> формат "Веб-страница, только HTML" -> в эту папку как gn.htm

# 2. Ингест + слияние с verified-ядром + пересборка корпуса и UI:
python3 ingest_sanpin.py --html ./gn.htm --merge --rebuild
```

Парсер HTML проверен на реальной структуре таблицы meganorm (азотная кислота, аммиак, бензол, бензапирен распознаны с верными ПДК и классами). Текстовый слой = нет OCR-риска на цифрах.

Если `извлечено веществ` около 360 или другого круглого числа, а не ~2495, значит документ разбит на несколько HTML-страниц, пришли мне число, добавим обход страниц.

## Запасной путь: PDF с текстовым слоем

Если найдёшь PDF ГН/СанПиН с выделяемым текстом (не скан): `python3 ingest_sanpin.py --pdf ./file.pdf --merge --rebuild`. Проверка логики без файла: `python3 ingest_sanpin.py --selftest`.

После этого `index_pro.html` и движок работают уже на расширенной базе. Наши 48 verified-веществ остаются как есть (приоритет), вещества из СанПиН добавляются сверху.

## Что произойдёт

- Парсер найдёт таблицы с колонками «наименование + ПДК + класс», вытащит вещества в нашу схему.
- Всё извлечённое помечается `confidence: needs_review` и сложится в `data/substances_sanpin.json`.
- Объединённый источник `data/substances_bulk.json` подхватит `corpus.py` автоматически.
- В конце выведется список веществ на ревью (где ПДК или класс пустые).

## Честно (статус UNVERIFIED на реальном PDF)

- Логика парсера проверена на синтетической таблице (`--selftest`), на реальном 600-страничном PDF СанПиН **не прогонялась** (у меня нет доступа к файлу). Первый запуск у тебя = первый реальный тест. Возможно, придётся подкрутить детект колонок под фактическую вёрстку таблицы 2.1.
- **ПДК это здоровье людей.** Всё из PDF идёт как `needs_review`. Перед тем как показывать заводу, прогнать review-лист глазами по тексту СанПиН. Агрегаторы у нас уже врали (ксилол, стирол) = официальный PDF это первоисточник, но OCR/парс может ошибиться на конкретной строке.
- Если pdfplumber плохо возьмёт таблицы (бывает на сложной вёрстке) = второй вариант это camelot-py или ручной экспорт таблицы в CSV, скрипт легко перенаправить на CSV. Скажи, если первый прогон даст мало строк, докрутим парсер под реальную вёрстку.
