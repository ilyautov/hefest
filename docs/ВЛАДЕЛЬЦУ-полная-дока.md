# HEFEST — полная дока для владельца (внутренний справочник)

> Это НЕ документ для заказчика (тот — `docs/О-СИСТЕМЕ.md`). Это твой рабочий справочник:
> где что лежит, как запустить, как показать, как расширить, какие правила нельзя нарушать,
> где «зарыты тела». Цель — чтобы ты сам мог запустить демо, объяснить любую часть и продолжить
> разработку (или передать её) без археологии по коду.

---

## 0. Самое главное за 60 секунд

- **Что:** RAG-ассистент по паспортам безопасности (СДС) для химзавода. Вопрос живым языком → ответ
  со ссылкой на раздел паспорта. Не уверен — отказывается. Работает офлайн (КИИ/152-ФЗ).
- **Стек:** FastAPI + локальный Ollama (`bge-m3` эмбеддинги, `qwen2.5:7b` генерация). ~40 Python-модулей,
  12 HTML-экранов, всё отдаётся одним сервисом. Опц. Qdrant, кросс-энкодер реранкер.
- **Ядро ценности:** три слоя доверия (отказ → подпись эксперта → сверка выдачи) + честные данные с провенансом.
- **Запустить демо:** `./setup.sh` (или `cd engine && RETRIEVER=lexical LLM_BACKEND=extractive uvicorn service:app`).
- **Святое правило:** НИКОГДА не выдумывать регуляторные значения. Всё из источника, с провенансом, `needs_review`.

## 2. Модули `engine/` (что за что отвечает)

**Пайплайн (запрос → ответ)**
- `service.py` — FastAPI-сервис, все ~40 эндпоинтов, раздача UI, middleware (API-ключ). Точка входа.
- `retriever.py` — гибридный + семантический ретривер (поиск разделов). Класс свопается по `RETRIEVER`.
- `backends.py` — сменные бэкенды эмбеддингов/генерации (Ollama/OpenRouter/GigaChat). Вендор-нейтральность.
- `cache.py` — семантический кэш ответов (кэшируется только дорогая генерация).
- `reranker_model.py` / `reranker_llm.py` — кросс-энкодер / LLM реранк (точность top-1 89%→92%).

**Слои доверия**
- `verification.py` — экспертная подпись ДАННЫХ вещества (verified/needs_review/rejected, кто/когда).
- `answer_review.py` — оценка ВЫДАЧИ (сверка ответа с первичкой). Отдельный слой.
- `hygiene.py` — аудит-лог запросов (с ротацией) + состояние паспортов + дашборд качества данных.

**Слои данных (обогащение, потребители)**
- `sanpin.py` — особые отметки СанПиН (О/К/А/Ф/кожа) + ПДК рабочей зоны.
- `sanpin_env.py` — экологические ПДК (атмосфера населённых мест / вода) — ОТДЕЛЬНО от рабочей зоны.
- `physchem.py` — физико-химия (темп. вспышки, НКПР/ВКПР, давление пара…) из PubChem.
- `transport.py` — номер ООН / класс груза / ERG из PubChem(DOT).
- `pubchem.py` — эталонная GHS-классификация (H-коды по ГОСТ 31340) + сверка с нашими знаками.
- `ghs_map.py` — 9 пиктограмм СГС + сигнальное слово.
- `baseline.py` — типовое руководство по группе (когда паспортных полей нет, с пометкой).
- `compat.py` / `registry.py` — совместимость хранения + реестр по площадкам.
- `rd_zone.py` — расчёт зоны заражения по РД 52.04.253-90. `quiz.py` — обучающий квиз.

**Сборщики данных (build-time, НЕ на рантайме)**
- `fetch_idlh.py` (NIOSH), `fetch_pubchem.py` (GHS), `fetch_physchem.py`, `fetch_transport.py` (PubChem),
  `fetch_synonyms.py` (Wikidata), `ingest_sanpin_env.py` (СанПиН DOCX), `ingest_sanpin.py`, `ingest_pdf.py` (OCR).

**Индексация / корпус**
- `corpus.py`, `build_semantic_index.py`, `extend_corpus.py`, `clean_data.py`, `apply_enrich.py`, `qdrant_index.py`.

**Eval (воспроизводимые метрики)**
- `eval_abstention.py` — safety-метрика отказа (покрытие / корректный отказ / галлюцинации).
- `evaluate.py`, `eval_extended.py`, `semantic_eval.py`, `semantic_hybrid_eval.py`, `semantic_rerank_eval.py`.

## 3. Эндпоинты (по группам)

- **Поиск/ответ:** `POST /ask` (главный — отказ/уточнение/первичка/кандидаты), `GET /search`.
- **Вещество:** `GET /substance/{name}`, `/substances/names` (автодополнение), `/passport/{name}`, `/card/{name}` (HTML+QR), `/qr/{name}`.
- **Аварийка:** `GET /emergency/{name}`, `/erg/{name}`, `POST /zone`, `/zone/substances`.
- **Нормативка:** `GET /sanpin/{name}`, `/ghs/{name}`, `/pubchem/{name}`, `/guidance/{name}`.
- **Доверие:** `POST /verify` + `GET /verification[/{name}]` (подпись данных); `POST /review` + `GET /reviews` (сверка выдачи).
- **Реестр/площадки:** `GET /plant/{name}`, `/registry[/{name}]`, `/compat`, `/export/registry.csv`.
- **Служебное:** `GET /health`, `/quality`, `/metrics`, `/audit`, `/quiz/{name}`.
- **UI:** `GET /` (home), `GET /{page}.html` (12 экранов из белого списка `_UI_PAGES`); `GET /doc/{name}` (рендер .md-доков).

## 5. Переменные окружения (профили)

Главные: `RETRIEVER` (lexical/semantic/qdrant), `LLM_BACKEND` (extractive/ollama), `OLLAMA_HOST`,
`ABSTAIN_THRESHOLD` (0.62), `CLARIFY_DELTA` (0.04), `RERANK`(+`RERANK_BACKEND`), `API_KEY`,
`SUBS_FILE`/`CORPUS_FILE`/`EMB_FILE`/`IDS_FILE` (имена файлов в `data/`), `AUDIT_LOG_MAX_BYTES`/`KEEP`.

**Профиль ДЕМО (без Ollama, офлайн из коробки):** `RETRIEVER=lexical LLM_BACKEND=extractive`.
**Профиль ПРОД (КИИ on-prem):** `RETRIEVER=semantic LLM_BACKEND=ollama OLLAMA_HOST=… RERANK=1` + clean data-файлы.
Полный список с комментариями — в `.env.example`.

## 7. Как запустить

**Демо локально (быстро, без Ollama):**
```bash
./setup.sh                       # проверит окружение и поднимет сервис
# или вручную:
cd engine && RETRIEVER=lexical LLM_BACKEND=extractive \
  SUBS_FILE=substances_clean.json CORPUS_FILE=corpus_full_clean.json \
  python3 -m uvicorn service:app --port 8000
# открыть http://127.0.0.1:8000
```

**Прод-режим (semantic, нужен Ollama с bge-m3 + qwen2.5):**
```bash
ollama pull bge-m3 && ollama pull qwen2.5:7b
cd engine && RETRIEVER=semantic LLM_BACKEND=ollama RERANK=1 \
  SUBS_FILE=substances_clean.json CORPUS_FILE=corpus_full_clean.json \
  EMB_FILE=embeddings_clean.npy IDS_FILE=embed_ids_clean.json \
  python3 -m uvicorn service:app --port 8000
```

**Docker:** `cp .env.example .env && docker compose up` (Ollama — на хосте, контейнер ходит по `host.docker.internal`).

## 8. Как показать (демо-сценарий)

> В демо-режиме (lexical) ретривер слабее семантического — некоторые запросы уходят в отказ или уточнение.
> Это **не баг для показа**: отказ и уточнение — наши киллер-фичи. Но для «чистого» ответа лучше прод (semantic).

1. **Карточка вещества** (`substance.html` → «хлор», «аммиак», «бензол»): показать слои — класс, ПДК рабочей
   зоны, физхимия, IDLH, особые отметки СанПиН, **экологические ПДК (атмосфера vs вода ≠ рабочая зона)**,
   транспорт ООН, первая помощь. У бензола — три разных ПДК и разный класс по средам (сильный момент).
2. **Консоль, чёткий вопрос** («чем опасен аммиак»): ответ + **первичка** (развернуть текст паспорта) +
   мягкое подтверждение «понял как про аммиак (X%)» + подсказки уточнения + панель сверки.
3. **Отказ** (вопрос вне базы, напр. «как испечь хлеб»): система честно отказывается — показать, что не выдумывает.
4. **Уточнение неоднозначности** («первая помощь при отравлении хлором» в lexical): чипы хлороформ/хлоропрен —
   «система не угадывает, спрашивает». Объяснить: вот так предотвращается ошибка ДО ответа.
5. **Автодополнение**: начать печатать «хлор» — выпадающий список.
6. **Аварийная карточка** (`emergency.html` → «хлор»): ООН, ДОПОГ, зона эвакуации ERG, IDLH, первая помощь.
7. **Этикетка+QR** (`label.html`): печатная этикетка, навести телефон → карточка.
8. **Дашборды:** `readiness.html` (готовность — подписи) и `reviews.html` (качество выдачи).

## 9. Как расширить (паттерн добавления чистого слоя данных)

Это отработанный паттерн (так сделаны физхимия, ООН, экологические ПДК). Повторяй его:

1. **Сборщик** `engine/fetch_<X>.py` или `ingest_<X>.py` — тянет данные из чистого источника по CAS/имени.
   *Правило: только public domain или офиц. акты РФ; храни сырое значение + источник; `needs_review`.*
2. **Файл** `data/<X>.json` (ключ — CAS), с `_meta` (источник, дисклеймер, юр. статус).
3. **Потребитель** `engine/<X>.py` — `for_cas(cas)` возвращает render-ready структуру с провенансом.
4. **Подключение** в `service.py` (`/substance`, при необходимости `/emergency`): `out["<X>"] = <X>.for_cas(...)`.
5. **UI** в `substance.html` (новый блок) — показать с пометкой источника и `needs_review`.
6. **Реиндекс не нужен** (рантайм-джойн по CAS). Проверь скриншотом.

Чистые источники в очереди: NIST WebBook (физхимия), офиц. аварийные карточки ЖД к ДОПОГ.

**Про лицензии (решение владельца, 2026-06-15):** слой физ-химии берётся через агрегат PubChem, который
цитирует и справочники с ограничительной лицензией (ICSC ILO/WHO и др.). Пока пилот **некоммерческий**
(денег не берём, чужой труд не перепродаём) — эти значения **оставляем** с полным провенансом и
`needs_review`, описания **локализованы** (`engine/physchem_l10n.py`), числа/единицы дословно (без пересчёта).
На коммерческом проде слой замещается паспортными данными завода. IARC (канцерогенность) не используется.

## 10. Святые правила проекта (не нарушать)

1. **Не выдумывать регуляторные значения.** ПДК, IDLH, зоны, номера ООН, первая помощь, GHS — только из
   авторитетного источника, с провенансом, `needs_review`. Цена ошибки = здоровье.
2. **Неуверенность — помечать.** Группа/типовое → «типовое по группе». Расхождение источников → сигнал
   аудитору, а не тихая правка.
3. **`verification.json` и `answer_reviews.json` — чистые в поставке.** Никаких фейковых подписей экспертов.
   Если ставил тестовые для скриншота — СБРОСЬ обратно в seed (это та самая «фабрикация доверия», от которой
   защищает сам продукт).
4. **Ядро — на юридически чистых данных** (public domain / офиц. акты РФ). Слой обогащения с
   ограничительной лицензией — только пока пилот некоммерческий, с провенансом; на проде замещается
   данными завода. Лицензию проверять перед коммерческим запуском.
5. **Локализуем описания, но не пересчитываем числа/единицы.** °F/mmHg оставляем как в источнике —
   пересчёт это вычисление, баг = цена ошибки. Перевод текста — да, перевод чисел — нет.
6. **Офлайн на рантайме.** Все `fetch_*`/`ingest_*` — build-time. В прод-контур едет только `data/`.

## 11. Где «зарыты тела» (нюансы, о которых легко забыть)

- **Lexical vs semantic.** Тесты/демо часто на `RETRIEVER=lexical` (без Ollama) — он путает «хлор» с
  «хлороформом». Прод — `semantic`. Не пугайся слабых ответов в lexical-демо.
- **Фоновые фетчи.** `physchem.json` и `transport.json` дособираются прогоном по 2029 CAS (`fetch_*` в фоне,
  ~час). Данные пишутся инкрементально, сервис читает на лету (mtime-кэш). Покрытие растёт само.
- **CAS-less вещества (~525).** Смеси/группы («алкил С7-9 амины») не имеют единого CAS — CAS-привязанные
  слои их не покрывают по объективной причине, не баг.
- **Скриншоты.** Playwright-модуля нет; используем закэшированный Chromium напрямую
  (`~/Library/Caches/ms-playwright/chromium-*/…/Google Chrome for Testing --headless --screenshot`).
- **Два слоя «уверенности».** Машинная `confidence`/`top_score` (алгоритм) ≠ экспертная подпись (человек).
  Не путать в объяснениях — это принципиально разные вещи.
- **Кэш ответов учитывает выбранное вещество** (ключ `chosen :: question`), чтобы уточнение не отдавало старый ответ.
