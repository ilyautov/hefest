# Дорожная карта: пилот → внедрение на завод

One-pager для показа заказчику. Честно: что уже готово, что делается на стороне завода, и каким
путём система переходит из пилота в безопасную промышленную эксплуатацию.

---

## Что это
AI-помощник по промышленной безопасности поверх паспортов безопасности (SDS, ГОСТ 30333) и нормативов
(ГН/СанПиН 1.2.3685-21, ГОСТ 12.1.007, СГС/ГОСТ 31340). Отвечает на вопросы по веществам, мерам первой
помощи, СИЗ, хранению, совместимости, аварийному реагированию (АХОВ: ООН/ДОПОГ, IDLH, зоны эвакуации).

**Контур:** полностью on-prem, air-gapped. Данные не покидают периметр (см. `DEPLOY.md`, раздел офлайн-гарантии).
Подходит под КИИ / 152-ФЗ.

**Принцип:** система — *поддержка принятия решений*. Первоисточник — действующий паспорт безопасности.
Система не выдумывает: где нет подтверждённого основания — честно отказывает и отправляет к паспорту.

## Делается на стороне завода (мы не имеем права сделать это за вас)

Это не пробелы продукта. Это шаги, которые по закону и по смыслу выполняет предприятие:

1. **Экспертная верификация ядра.** Ответственный (инженер ОТ/ПБ, эколог) сверяет значения по
   ИХ номенклатуре с ИХ паспортами и ставит подпись (через интерфейс/`/verify`). До подписи всё помечено
   «требует проверки». Цена ошибки = здоровье, поэтому подпись ставит человек, а не алгоритм.
2. **Классификация значимости по КИИ** и (при необходимости) аттестация по требованиям ФСТЭК.
3. **Интеграция с инфраструктурой:** их AD/LDAP для аутентификации, их железо (сайзинг под GPU/CPU Ollama).
4. **Загрузка их паспортов:** их SDS прогоняются через конвейер (OCR доказан для сканов) с проверкой человеком.

## Путь внедрения (фазы)

**Фаза 0 — Демо/пресейл (1 встреча).**
Показ на 10–20 ИХ реальных веществ, заранее сверенных их же экспертом: система даёт точные ответы
со значком «✓ подтверждено экспертом», а на вопросах вне базы — честно отказывает. Главный тезис:
*не «у нас 1493 вещества», а «ваши вещества, проверенные вашим инженером, и система молчит, где не знает».*

**Фаза 1 — Пилот на одном участке/цехе (2–4 недели).**
- Загрузка паспортов участка, верификация ядра (десятки веществ) ответственным.
- Калибровка порога отказа на их вопросах (`eval_abstention.py`).
- Развёртывание в их контуре (Docker, офлайн-проверка), подключение аутентификации.
- Критерий приёмки: см. `docs/ЧЕКЛИСТ-приёмки.md`.

**Фаза 2 — Расширение.**
Постепенный охват остальных цехов/веществ; накопление подписанного ядра; регламент актуализации
(обновления ГН/СанПиН, новые ревизии паспортов).

---

## Где проходит граница ответственности
Система отвечает по подтверждённым данным и помечает неподтверждённые. Решения по охране труда,
реагированию и эвакуации принимает ответственный специалист на основании паспорта безопасности и
нормативных расчётов (напр. зоны — по РД 52.04.253-90, не по справочному ERG). Это зафиксировано
в дисклеймере на каждом экране и в ответах системы.
