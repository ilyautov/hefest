# Чеклист приёмки и верификации (для эксперта завода)

Заполняет ответственный специалист предприятия (инженер по ОТ/ПБ, эколог) при приёмке пилота.
Цель — зафиксировать, что система готова к эксплуатации на данном участке и кто за это отвечает.

---

## 1. Верификация данных (safety-критично)

Для каждого вещества участка ответственный сверяет значения с действующим паспортом безопасности
и ставит подпись. До подписи значение помечено «требует проверки» и так и показывается пользователю.

- [ ] Составлен перечень веществ участка (из реестра завода / `/plant`).
- [ ] По каждому веществу сверены критичные поля: **класс опасности, ПДК, первая помощь, СИЗ, хранение**.
- [ ] Расхождения с паспортом зафиксированы и либо исправлены в данных, либо вещество помечено `rejected`.
- [ ] Поставлены подписи (`/verify`: кто, должность, дата) — проверяется в `/verification` (% подписанного ядра).
- [ ] Для АХОВ: ООН-номер/ДОПОГ, IDLH и зоны эвакуации сверены; подтверждено, что зоны используются
      как ориентир, а расчёт ведётся по РД 52.04.253-90.

**Ответственный за верификацию:** ________________  Должность: ____________  Дата: __________

---

## 2. Качество ответов (проверка на отказ и точность)

- [ ] Прогнан `eval_abstention.py` на вопросах участка; зафиксированы метрики:
      покрытие ___%, корректный отказ ___%, **галлюцинации ___%** (целевое — 0%).
- [ ] Порог отказа `ABSTAIN_THRESHOLD` откалиброван под их вопросы (по умолчанию 0.62).
- [ ] Выборочно проверены 10–15 реальных вопросов смены: ответы корректны и со ссылкой на раздел паспорта.
- [ ] Проверено, что на вопрос вне базы система отказывает, а не выдумывает.

---

## 3. Контур и безопасность (КИИ / 152-ФЗ)

- [ ] Развёрнуто в закрытом контуре (Docker/compose по `DEPLOY.md`).
- [ ] **Офлайн-проверка пройдена:** при заблокированном исходящем трафике `/ask` и `/substance` работают
      (генерация через локальный Ollama). Внешних вызовов в рантайме нет.
- [ ] Подключена аутентификация предприятия (AD/LDAP) — доступ только авторизованным.
- [ ] Включён аудит-лог запросов (`data/audit_log.jsonl`): видно «кто что спросил».
- [ ] Согласовано со службой ИБ; при необходимости — классификация значимости по КИИ.
- [ ] Сайзинг железа подтверждён (модели bge-m3 + qwen2.5 запускаются с приемлемой задержкой).

---

## 4. Эксплуатация и актуализация

- [ ] Назначен ответственный за обновление данных (новые ревизии паспортов, изменения ГН/СанПиН).
- [ ] Определён регламент: периодичность пересборки данных и повторной верификации.
- [ ] Проведено короткое обучение пользователей (смена/диспетчер): как читать значок верификации
      и дисклеймер, что первоисточник — паспорт.
