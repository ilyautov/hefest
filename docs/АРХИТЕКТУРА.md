# Архитектура системы (схемы + принципы)

> Визуальная карта системы: контур развёртывания, поток запроса, слои данных, слои доверия и карта модулей.
> Дополняет [О-СИСТЕМЕ.md](О-СИСТЕМЕ.md) (раздел 4 — текстовое описание архитектуры). Все диаграммы — ASCII,
> рендерятся офлайн (продукт air-gap, без внешних CDN). Числа — из текущего состояния, сверены с кодом/данными.

---

## 1. Контур развёртывания (что внутри периметра завода)

Всё работает **на железе предприятия, без интернета на рантайме**. Внешняя сеть нужна только на этапе
подготовки данных (сборщики), и это происходит вне прод-контура.

```
        ┌──────────────────── ИНТЕРНЕТ (только BUILD-TIME, вне прод-контура) ────────────────────┐
        │   PubChem/NIH · NIOSH · СанПиН-таблицы · Wikidata · ДОПОГ/ERG                            │
        └───────────────────────────────────┬─────────────────────────────────────────────────────┘
                                             │  fetch_*.py / ingest_*.py  (разово, офлайн-подготовка)
                                             ▼
                                      data/*.json  (сырьё + провенанс + needs_review)
══════════════════════════════════ ПЕРИМЕТР ПРЕДПРИЯТИЯ (AIR-GAP) ══════════════════════════════════
                                             │  в прод едет ТОЛЬКО папка data/
                                             ▼
   ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
   │  Сервер завода (CPU/GPU; Apple Silicon или серверная карта)                                   │
   │                                                                                               │
   │   Браузер оператора ──HTTP──►  FastAPI (service.py, 43 эндпоинта)                              │
   │   (18 HTML-экранов)                  │                                                         │
   │                                      ├──► Ретривер (поиск по разделам)                          │
   │                                      ├──► Локальный Ollama (эмбеддинги bge-m3 / генерация qwen) │
   │                                      ├──► Слои данных (джойн по CAS): physchem, sanpin, ...     │
   │                                      └──► Аудит-лог (audit_log.jsonl, append-only)              │
   │                                                                                               │
   │   НИКАКИХ внешних сетевых вызовов на рантайме. Данные не покидают периметр.                     │
   └─────────────────────────────────────────────────────────────────────────────────────────────┘
```

**Почему так:** требование КИИ (187-ФЗ) и 152-ФЗ — чувствительные данные не уходят наружу. Все `fetch_*.py`/
`ingest_*.py` — это *build-time* инструменты; на рантайме система общается только с локальным Ollama/Qdrant.

## 2. Поток обработки запроса (RAG-конвейер)

```
   Вопрос пользователя ("первая помощь при отравлении хлором")
        │
        ▼
  [1] ЭМБЕДДИНГ вопроса ──────────────► bge-m3 (Ollama), 1024-мерный вектор
        │                               (смысл вопроса → числа)
        ▼
  [2] ПОИСК по 25 970 разделам паспортов
        │   • семантика (косинусная близость векторов)
        │   • + лексический сигнал (BM25 / char-ngram)
        │   • + плант-скоуп (ограничить веществами завода)
        │   • + интент раздела (первая помощь / хранение / …)
        │   • + опц. кросс-энкодер реранкер (bge-reranker-v2-m3): top-1 89% → 92%
        ▼
  [3] ГЕЙТ ОТКАЗА ──────────────────── score < порога (0.62)?  ──ДА──►  честный отказ
        │  «нет уверенного основания»                                  (НЕ генерируем)
        │  НЕТ
        ▼
  [4] ГЕЙТ УТОЧНЕНИЯ ───────────────── 2+ разных вещества с близким score?  ──ДА──►  «какое именно?»
        │  (хлор / хлороформ / хлоропрен)                                    (спрашиваем, не угадываем)
        │  НЕТ
        ▼
  [5] ГЕНЕРАЦИЯ ответа ─────────────── qwen2.5:7b (Ollama) СТРОГО из найденных разделов
        │  (в демо — экстрактивная сборка без модели, нулевой риск галлюцинаций)
        ▼
   Ответ + первичка (текст разделов) + кандидаты + статус верификации + цитаты [1][2][3]
```

Модули: `retriever.py` (поиск), `backends.py` (адаптер эмбеддингов/генерации), `reranker_*.py` (реранк),
сборка ответа и гейты — в `service.py` (`/ask`, `/search`).

## 3. Слои данных и сборка карточки (джойн по CAS)

Карточка вещества — это не одна таблица, а **сборка из слоёв по ключу CAS** на рантайме. Каждый слой —
из своего источника, со своим провенансом, всё `требует проверки` до подписи эксперта.

```
   BUILD-TIME (офлайн)               data/*.json              RUNTIME (джойн по CAS)
   ──────────────────               ───────────              ─────────────────────
   ingest_pdf.py     ─► паспорта ─►  corpus_full_clean.json ─┐
   build_semantic…   ─► эмбеддинги ► embeddings_clean.npy    ├─►  РЕТРИВЕР ──► ответ
                                                             │
   ingest_sanpin.py  ─►             sanpin (ПДК раб. зоны) ──┤
   ingest_sanpin_env ─►             sanpin_atmo / water ─────┤
   fetch_idlh.py     ─►             idlh.json (NIOSH) ───────┤
   fetch_pubchem.py  ─►             pubchem_ghs.json ────────┼─►  КАРТОЧКА вещества
   fetch_physchem.py ─►             physchem.json ───────────┤   /substance · /emergency
   fetch_transport.py─►             transport.json (ООН) ────┤   /ghs · /erg · /zone
   fetch_synonyms.py ─►             synonyms.json (Wikidata)─┤
   (курация)         ─►             ahov_cards / erg / rd ───┘   потребители — раздел 5

   Принцип: храним СЫРОЕ значение + источник; ничего не пересчитываем; needs_review.
```

**Физ-химия — особый слой.** `physchem.json` — агрегат справочников через PubChem (HSDB, CAMEO, NIOSH, ICSC
и др.). На выдаче `physchem.py` применяет `physchem_l10n.py`: **локализует описания** на русский и **схлопывает
дубли**, объединяя источники; числа/единицы оставляет дословно (без пересчёта — пересчёт это вычисление,
а баг = «цена ошибки»). На коммерческом проде слой замещается паспортными данными завода.

## 4. Три слоя доверия (почему система safety-grade)

Прямой ответ на главный риск ИИ — **уверенная неправда**. Доверие зашито в три слоя, а не в дисклеймер.

```
   ┌─ ДО ответа ───────────────────────────────────────────────────────────────────────┐
   │ СЛОЙ 1 — ОТКАЗ ВМЕСТО ГАЛЛЮЦИНАЦИИ                                                  │
   │ score < порога → система молчит и шлёт к паспорту. 100% покрытия / 0% галлюцинаций. │
   └────────────────────────────────────────────────────────────────────────────────────┘
   ┌─ на данных ───────────────────────────────────────────────────────────────────────┐
   │ СЛОЙ 2 — ЭКСПЕРТНАЯ ПОДПИСЬ                                                          │
   │ требует проверки → подтверждено экспертом → отклонено. Кто/когда. Дашборд готовности.│
   └────────────────────────────────────────────────────────────────────────────────────┘
   ┌─ ПОСЛЕ ответа ────────────────────────────────────────────────────────────────────┐
   │ СЛОЙ 3 — СВЕРКА ВЫДАЧИ С ПЕРВИЧКОЙ                                                  │
   │ человек видит исходный раздел, оценивает (retrieval/extraction), подписывает оценку.│
   └────────────────────────────────────────────────────────────────────────────────────┘
```

Модули: `service.py` (гейт отказа/уточнения), `verification.py` (подписи данных), `answer_review.py` (сверка
выдачи). Экраны: `readiness.html`, `reviews.html`.

## 5. Карта модулей (что за что отвечает)

| Группа | Модули | Роль |
|---|---|---|
| **Ядро RAG** | `retriever.py`, `corpus.py`, `backends.py`, `reranker_model.py`, `reranker_llm.py`, `qdrant_index.py` | поиск по разделам, адаптер моделей, реранк, опц. векторная БД |
| **Слои данных** (джойн по CAS) | `sanpin.py`, `sanpin_env.py`, `physchem.py`+`physchem_l10n.py`, `transport.py`, `ghs_map.py`, `pubchem.py`, `rd_zone.py`, `waste.py`, `compat.py` | ПДК/эко-ПДК, физхимия (локализ.), ООН, GHS, зоны, отходы, совместимость |
| **Нормативка / ГОСТ** | `normative.py`, `gost_sections.py`, `audit_versions.py` | реестр версий актов, карта 16 разделов, аудит редакций |
| **Доверие** | `verification.py`, `answer_review.py` | подпись данных, сверка выдачи |
| **Фичи** | `registry.py`, `quiz.py`, `baseline.py` | реестр площадок, проверка знаний, базовая сборка карточки |
| **Инфра** | `service.py`, `hygiene.py`, `cache.py`, `generate_ui.py` | API+UI, аудит/авторизация, кэш, генерация экранов |
| **Build-time** (вне прод-контура) | `fetch_idlh/pubchem/physchem/transport/synonyms.py`, `ingest_pdf/sanpin*.py`, `build_semantic_index.py` | сборка данных и эмбеддингов из чистых источников |

## 6. Технологический стек

| Слой | Технология | Примечание |
|---|---|---|
| Эмбеддинги | **bge-m3** (1024-мерные) | multilingual, локально через Ollama |
| Генерация | **qwen2.5:7b** | локально; в демо — экстрактивная сборка без модели |
| Реранк (опц.) | **bge-reranker-v2-m3** | кросс-энкодер, top-1 89% → 92% |
| Хранилище векторов | `numpy`-матрица или **Qdrant** | Qdrant — опц. профиль в Docker |
| API + UI | **FastAPI**, 43 эндпоинта, 18 HTML-экранов | один сервис отдаёт и API, и UI |
| Вендор-абстракция | `backends.py` | Ollama ↔ OpenRouter ↔ GigaChat одной переменной окружения |
| Развёртывание | **Docker + docker-compose** | офлайн / air-gap; в контур едет только `data/` |
